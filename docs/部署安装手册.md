# 群芳教育管理系统 · 部署安装手册

> 本手册面向拿到源码后的第一次安装：先在**你自己电脑上跑起来**（约 10 分钟），再选择**上线到云端**（两条路线任选）。
> 每一步都写了"预期看到什么"，照着核对就不会迷路。遇到问题先看最后的「常见问题」。

---

## 〇、安装前你需要知道的三件事

1. **这套系统不需要买服务器**。它跑在 Serverless 云平台上：Cloudflare（海外，有免费额度）或腾讯云 CloudBase（国内直连，约 19.9 元/月起）。
2. **你会一点命令行就够了**。所有命令都可以直接复制粘贴。
3. **数据在你自己手里**。数据库、文件都在你自己账号的云资源里，随时可迁走。

**你需要准备**：一台电脑（Windows / macOS 均可）、已安装 Node.js 20 或更高版本（https://nodejs.org 下载 LTS 版，安装时一路下一步）。验证方法：终端里输入 `node -v`，能显示版本号即可。

---

## 一、路线 A · 在你电脑上跑起来（体验/试用，约 10 分钟）

### 第 1 步：安装依赖

在项目根目录（`qunfang-edu/`，即有 `package.json` 的那层）打开终端，执行：

```bash
npm install
```

预期：最后没有 `error` 字样。中间出现黄色警告（warning）是正常的，不用管。
耗时参考：1–3 分钟（取决于网速）。

### 第 2 步：配置登录密钥

把示例配置复制一份：

```bash
cp .dev.vars.example .dev.vars
```

然后用任意文本编辑器打开 `.dev.vars`，把 `change-me-to-a-long-random-string` 换成**任意一长串随机字符**（比如随手敲 30 个字母数字）。这串字符只在你本机用于加密登录凭证，不会上传。

### 第 3 步：初始化数据库

```bash
npm run db:migrate:local
npm run db:seed:local
```

预期：
- 第一条命令会显示 `1001_init.sql`、`0002_…sql`、`0003_…sql` 三个迁移被应用（共 3 个，数量对上即可）；
- 第二条命令末尾显示执行成功（约 33 条语句）。

这一步建了 20 张表，并灌入一份**虚构的演示数据**：2 个校区、16 名教师、40 名学员、40 张课时卡、146 节课。

### 第 4 步：构建前端

```bash
npm run build
```

预期：末尾出现 `✓ built in …`。这一步把界面编译成浏览器能直接运行的文件，输出在 `web/dist/`。

### 第 5 步：启动

```bash
npm run dev:api
```

预期：终端出现 `Ready on http://localhost:8787`（首次启动可能要等 10–30 秒）。

### 第 6 步：打开浏览器体验

访问 **http://localhost:8787**，用演示账号登录（密码统一 `Passw0rd!`）：

| 手机号 | 角色 | 建议体验 |
|---|---|---|
| 13800000001 | 超级管理员 | 全局看板、校区切换 |
| 13800000002 | 校区管理员（阳光广场） | **重点看"忙闲总览"和"排课周历"** |
| 13800000011 | 教师（阳光广场 · 张雨薇） | 我的课表、点名 |
| 13800000021 | 家长（王芳） | 孩子课表、课时卡余额 |

> 建议第一个登录 13800000002，进去后点「排课中心 → 忙闲总览」——这是整套系统的核心页面。

**用完怎么停**：在终端按 `Ctrl + C`。

## 二、换成你自己的品牌（1 分钟）

打开 `web/src/config/brand.ts`，改一行：

```ts
export const brandName = '群芳教育';   // ← 把引号里换成你的机构名
```

保存后重新执行 `npm run build`（第 4 步），刷新浏览器——登录页、管理后台、教师端、家长端的品牌名和左上角圆标会全部变成你的。**不需要动任何其他文件。**

想连配色一起换：`web/src/index.css` 顶部的 `--color-primary` 等 22 个 `--ds-*` 设计变量集中控制全部视觉，改它们即可，同样不碰业务代码。

## 三、路线 B · 上线到 Cloudflare（海外入口，免费额度够用）

适合：机构用户在海外，或你暂时不想花云服务费。
**国内直连注意**：Cloudflare 免费版分配的 `*.workers.dev` 域名在中国大陆被 DNS 污染，打不开。国内用户请走路线 C，或给 Worker 绑定自定义域名（见第 3.9 步说明）。

### 第 1 步：注册并登录 Cloudflare

1. 到 https://dash.cloudflare.com 注册一个免费账号；
2. 在终端执行 `npx wrangler login`，浏览器会弹出授权页，点「Allow」。

### 第 2 步：创建你自己的数据库和缓存

> 源码里的 `wrangler.toml` 写的是原开发者的资源 ID，**必须换成你自己的**。

```bash
npx wrangler d1 create qunfang
```

预期输出里有 `database_id = "xxxxxxxx-…"`，复制它。

```bash
npx wrangler kv namespace create CACHE
```

预期输出里有 `id = "xxxxxxxx"`，复制它。

### 第 3 步：改配置文件

用编辑器打开 `wrangler.toml`，替换两处：

```toml
database_id = "把你复制的 D1 database_id 粘到这里"
...
id = "把你复制的 KV id 粘到这里"
```

### 第 4 步：设置线上密钥

```bash
npx wrangler secret put JWT_SECRET
```

按提示粘贴一串随机字符（和本地那串可以不同）。

### 第 5 步：初始化线上数据库

```bash
npm run db:migrate:remote
npm run db:seed:remote
```

### 第 6 步：部署上线

```bash
npm run deploy
```

预期：末尾出现 `Deployed qunfang-edu triggers` 和一个 `https://qunfang-edu.<你的子域>.workers.dev` 地址。

> 若提示名字被占用（同名 Worker 太多），把 `wrangler.toml` 第一行 `name = "qunfang-edu"` 改成别的名字再部署。

### 第 7 步（可选但推荐）：验证

把冒烟测试脚本指向你的线上地址，一键自验 260 项断言：

```bash
node scripts/smoke-test.mjs https://你的地址.workers.dev
```

预期：末尾显示 `结果：10 通过，0 失败`。其余 8 个脚本（smoke-test-m2 ~ m6、r1、batch2、r8）同理，全部跑完是 260 项。

### 关于国内访问

`workers.dev` 域名在大陆无法直连是网络层面的已知现状，与代码无关。解决方式二选一：
- **换成腾讯云部署**（路线 C，国内直连，推荐国内机构）；
- **绑定自己的域名**：任何自有域名接入 Cloudflare 后都可以作为 Worker 的自定义域名，国内可直连（延迟约 200–400ms，内部管理系统够用）。

## 四、路线 C · 上线到腾讯云 CloudBase（国内直连，推荐国内机构）

适合：机构用户在中国大陆，要求不翻墙直接访问。

**难度提示（如实说明）**：这条路线的准备工作比 Cloudflare 多——需要开通云开发环境、创建 PostgreSQL、在数据库里安装 `exec_sql` 通道函数、创建 API Key。如果你不熟悉云开发控制台，建议：① 优先走路线 B + 自定义域名；② 或购买卖家的代部署服务（见商品页）。

### 第 1 步：开通环境

1. 注册/登录腾讯云，进入云开发 CloudBase 控制台（https://tcb.cloud.tencent.com）；
2. 创建环境（基础版即可，约 19.9 元/月起；新用户可先领免费体验）；
3. 记下**环境 ID**（形如 `xxxx-xxxx`）。

### 第 2 步：初始化数据库

在控制台开通 PostgreSQL 数据库后，用 tcb CLI 推送迁移（在项目根目录）：

```bash
npm install -g @cloudbase/cli
tcb login
tcb migration up -e 你的环境ID
```

迁移文件已备好在 `cloudbase/migrations/`（含建表、`exec_sql` 通道函数与演示数据）。

### 第 3 步：配置部署凭据

1. 在控制台「环境 → API Key」创建一张服务端 API Key，**完整复制**（只显示一次）；
2. 保存到项目根目录 `.cloudbase-apikey.txt`（此文件已在 `.gitignore` 中，不会泄露）；
3. 参考 `scripts/build-cloudbase.mjs` 里的说明配置环境信息。

### 第 4 步：部署

```bash
npm run cloudbase:deploy
```

预期：脚本自动完成「构建前端 → 打包服务端 → 安装依赖 → 部署云函数」，末尾输出访问地址（形如 `https://你的环境ID.service.tcloudbase.com/`）。

> 平台测试域名首次访问会显示腾讯云"页面访问提示"中间页，点「确定访问」后进入——这是平台行为，不是部署失败。要移除中间页需配置正式服务别名/自定义域名。

## 五、常见问题

**Q1：启动时报错 "Port 8787 is already in use"**
说明有另一个程序占着这个端口（常见于之前启动过没关干净）。Windows 下找到并结束它：
```bash
netstat -ano | findstr :8787     # 记下最后一列的数字（PID）
taskkill /F /PID 那个数字
```
或者改端口启动：`npx wrangler dev --port 8788`。

**Q2：构建时报错，提到 `web/dist` 删除失败**
`web/dist` 被正在运行的 dev 服务占用。先 `Ctrl + C` 停掉所有终端里的服务，确认第 Q1 的端口已释放，再重新 `npm run build`。

**Q3：登录一直报错/一登录就掉**
九成是 `.dev.vars` 没配或 `JWT_SECRET` 留着示例值。回到路线 A 第 2 步检查。

**Q4：演示数据怎么清掉，换成我自己的数据？**
两种做法：① 演示数据是虚构的，直接在系统里逐条改成你的（适合量小）；② 想要干净空库：本地删掉 `.wrangler/` 目录后重跑第 3 步的 `db:migrate:local`（**跳过** `db:seed:local`），就是一个全空的系统。线上同理（删除 D1 库重建后只跑迁移）。

**Q5：怎么确认我买到的这套代码是完整的？**
跑冒烟测试（路线 A 第 5 步启动后，新开一个终端）：

```bash
node scripts/smoke-test.mjs     http://localhost:8787
node scripts/smoke-test-m2.mjs  http://localhost:8787
node scripts/smoke-test-m3.mjs  http://localhost:8787
node scripts/smoke-test-m4.mjs  http://localhost:8787
node scripts/smoke-test-m5.mjs  http://localhost:8787
node scripts/smoke-test-m6.mjs  http://localhost:8787   # 需先灌演示数据
node scripts/smoke-test-r1.mjs  http://localhost:8787
node scripts/smoke-batch2.mjs   http://localhost:8787
node scripts/smoke-r8.mjs       http://localhost:8787
```

9 个脚本全部 `0 失败`（合计 260 项断言），说明认证、权限、排课冲突、课时账实一致、审批通知等核心链路全部正常。

**Q6：手机上能用吗？**
能。系统是响应式网页，手机浏览器直接打开你的线上地址即可，最小适配到 375px 宽（覆盖主流机型）。也可以把地址加到微信收藏或公众号菜单。

**Q7：以后怎么升级 / 改代码？**
改完代码后：本地先跑 `npm run typecheck` 和 `npm run build` 确认无误，再执行 `npm run deploy`（Cloudflare）或 `npm run cloudbase:deploy`（腾讯云）。数据库结构变更请按 `migrations/` 目录里的编号规则新增迁移文件，不要直接改线上库。
